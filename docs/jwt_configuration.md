# RSA configuration

Normal application startup now requires a unique RSA key pair. `JWT_SECRET` is not an RSA configuration property and is no longer used by the deployment templates. Never use the repository development key on a reachable installation.

The examples below are for a **new isolated installation**. They have not been executed against the VPS. For its existing state and key migration, follow the [audit recovery plan](project_review_2026-10-24.md#concrete-recovery-and-rollout-sequence) first.

## Generate and store a pair

On a machine with OpenSSL, choose a protected directory outside the checkout and backups shared with other users. The variable must name a new directory; these commands intentionally do not overwrite an existing directory.

```bash
set -eu
umask 077
DETE_KEY_DIR="$HOME/.config/dete-keys-new"
mkdir -p "$HOME/.config"
mkdir "$DETE_KEY_DIR"
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:3072 -out "$DETE_KEY_DIR/private.pem"
openssl pkey -in "$DETE_KEY_DIR/private.pem" -pubout -out "$DETE_KEY_DIR/public.pem"
```

The private PEM must use PKCS#8 (`BEGIN PRIVATE KEY`); the public PEM must use X.509 (`BEGIN PUBLIC KEY`). Plain Base64 encodings of those DER formats are also accepted. Keep the pair stable across restarts and back it up securely. Do not print the private key, add it to Git, or paste it into a Helm values file.

## Local processes and full Compose

```bash
export AUTH_JWT_PRIVATE_KEY="$(cat "$DETE_KEY_DIR/private.pem")"
export AUTH_JWT_PUBLIC_KEY="$(cat "$DETE_KEY_DIR/public.pem")"
export SECURITY_JWT_PUBLIC_KEY="$AUTH_JWT_PUBLIC_KEY"
docker compose -f infra/docker-compose-full.yml config --quiet
```

Auth reads `AUTH_JWT_PRIVATE_KEY` and `AUTH_JWT_PUBLIC_KEY`. Gateway, account, order, audit, and market-data validators read `SECURITY_JWT_PUBLIC_KEY`. Full Compose maps the validator public key to auth's public-key property too. Start services only in the intended isolated environment after its database/broker configuration is checked.

## Helm

For a new namespace/installation, provision the Secret separately from Helm:

```bash
kubectl create secret generic dete-jwt-keys --namespace dete \
  --from-file=private-key="$DETE_KEY_DIR/private.pem" \
  --from-file=public-key="$DETE_KEY_DIR/public.pem"
```

Set `secrets.jwtKeySecretName` when using a different Secret name. Auth alone receives the private key; validators receive the public key. No Secret is generated by the chart. Kubernetes Secret access and storage protection must be configured by the operator.

## Tests

Gradle test tasks explicitly set `security.jwt.allow-development-key=true` for synthetic test credentials. Normal application tasks do not. Key-provider unit tests separately verify that missing, shared-development, and mismatched configurations are rejected with the opt-in disabled. This test opt-in is not a deployment setting.
