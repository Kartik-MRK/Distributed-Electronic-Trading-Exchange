# On-demand market simulation

The simulator now runs only for a persisted session started from the authenticated trading terminal. Users can request 30, 60, or 120 seconds. The API is `POST /market-simulation/start` with `{"durationSeconds":60}` and `GET /market-simulation/status`; both validate the user's JWT at the gateway and the simulator service.

PostgreSQL stores the session in its own `simulator` schema. A transaction-scoped advisory lock serializes start and recovery requests, while a partial unique index prevents two live session rows. The active session has an owner UUID, fencing token, lease deadline, and a fixed server-side expiry. The worker checks the persisted owner/fence before bot submissions. Its order API calls have two-second connect/read timeouts; a session has at most 15 maker levels on each side per market and 15 outstanding taker orders per market. New bot submissions are paced by one shared limiter (8 per second by default, configurable from 1 to 12). Only one worker thread is created for a running session; no simulator polling thread runs while idle.

On completion, the service stops new submissions and queries/cancels active orders using only the maker and taker bot credentials through the existing order API. Failed cleanup leaves the session in `STOPPING`, blocking a replacement session. A start request after the maximum duration plus the 15-second grace period retries cleanup under the same database lock. This also recovers abandoned sessions after a service restart without polling while idle. User-owned orders, balances, trades, candles, and market history are not reset or deleted.

## Deployment

The simulator's Flyway migration creates the schema and session table. Kubernetes supplies the existing PostgreSQL credentials and points the service at `currentSchema=simulator`; it also uses the existing `public-key` JWT secret. Deploy the gateway and simulator images with the normal Helm release; no new infrastructure or secret is required. If deploying behind the VPS Nginx configuration generated by `scripts/update_nginx.py`, reload that configuration so `/market-simulation` reaches the gateway. For a local run, set `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`, and the existing `SECURITY_JWT_PUBLIC_KEY` as used by the other services. `SIMULATOR_ENABLED=false` disables starts.

Metrics are exported through the existing Actuator/Prometheus endpoint: session starts, start conflicts, failures, recoveries, cleanup failures, and bot submissions/fills tagged by market and bot role. The workload is bounded by the configured 120-second maximum, the three markets, maker depth, taker order cap, and one active worker. Cleanup uses up to 24 short-lived threads and a 12-second wait bound; a cleanup that cannot be confirmed keeps the session blocked for retry.

The PostgreSQL concurrency test uses Testcontainers and is skipped by Testcontainers when Docker is unavailable. Run it with `gradlew :services:simulator:test` in an environment with Docker to exercise concurrent service instances against PostgreSQL.
